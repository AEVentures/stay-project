# Contributing to the Stay Project

Thank you for considering contributing. This work matters.

## Ways to contribute

- **Code:** build features, fix bugs, improve tooling.
- **Crisis-line accuracy:** verify, add, or correct hotline data with an
  official source — see [docs/RESOURCES.md](docs/RESOURCES.md).
- **Copy and safe messaging:** improve clarity and accessibility of warning
  signs, how-to-help guides, and resource pages.
- **Translation:** localize content for non-English speakers.
- **Design and accessibility:** improve readability and usability, especially
  for people on older or low-bandwidth devices.
- **In Memory:** if you've lost someone to suicide, you're welcome to add
  them to our opt-in memorial in [docs/IN_MEMORY.md](docs/IN_MEMORY.md).

## Before you write user-facing copy

Read [docs/SAFE_MESSAGING.md](docs/SAFE_MESSAGING.md). It summarizes WHO and
AFSP guidance this project follows, and it is a required read before editing
any content about suicide, warning signs, or personal stories.

## Getting started

See [docs/GETTING_STARTED.md](docs/GETTING_STARTED.md) for install, build,
test, and project structure.

For the roadmap, see [docs/ROADMAP.md](docs/ROADMAP.md).

## Guidelines

- Keep changes focused. One concern per pull request.
- Write clear commit messages.
- Add or update tests when adding logic.
- Keep components small and single-purpose.
- Use named exports.
- Follow the existing code style.
- Cite an official source for any statistic or crisis-line number.

## Reporting issues

Use GitHub Issues. Include:

- A clear title
- Steps to reproduce, if it is a bug
- Expected and actual behavior
- Your environment (OS, browser, Node version)

## Need help?

Open a GitHub Discussion or comment on an issue. We will respond as quickly
as we can.
